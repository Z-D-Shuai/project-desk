# 启动日志修复与最终 Smoke 复验

日期：2026-11-18；版本 v1.0.0。仅修改启动相关实现、测试及交付说明，没有变动业务、SQLite 或 UI。

## 原因

`logs/server.log` 为 Archive 属性，非只读，可正常读取。在本次执行身份/环境下，Node v24.21.0 以 r+ 或 a 打开均返回 EPERM；PowerShell 只尝试获取写句柄、不写入内容，也返回访问被拒绝。不是根据报错猜测 Node 版本、只读属性或文件内容问题；底层权限拒绝的具体来源未进一步确证，未改变系统权限。

程序层面的直接原因已确认：`scripts/launch.mjs` 在创建服务子进程前，无保护地 `openSync(log,'a')`，将可选文件日志视为启动硬依赖；运行时 `writeSync` 失败也未捕获。因此日志不可写就会直接终止启动，或使运行中的日志监听异常退出。

## 最小修复

- `scripts/startup-log.mjs`：正常情况下仍追加原日志。创建、打开、写入、关闭失败时只停用文件日志，明确显示错误码和文件位置；stdout/stderr 继续显示在启动窗口。处理部分写入，释放自有句柄，错误只提示一次。
- `scripts/launch.mjs`：接入该日志模块，保留原版本/工作区核验、启动流程、浏览器入口及进程管理；文件日志不可用时正确提示查看当前窗口。
- `start.bat`：失败提示不再只指向可能不可用的日志文件。
- `tests/startup.test.mjs`：追加历史、打开/建目录被拒绝、运行中写入失败、部分写入四项回归。

没有删除/覆盖原日志，没有修改 ACL、系统安全设置、Node 安装、业务代码、数据库、UI 或提醒任务，没有改到其他目录写日志。文件日志不可用时，本次会话输出仅在启动窗口保留，关闭后不会补写；具备写权限的环境继续正常追加文件。
